Fault Localization with Program Slicing

An experimental evaluation of hybrid spectrum-based fault localization on real-world Java bugs from Defects4J.

This research investigates whether dynamic program slicing can reduce the statement search space of spectrum-based fault localization (SBFL) while preserving — or improving — its ability to rank the true faulty statement. Motivation

Research Purpose

Spectrum-based fault localization (SBFL) ranks program statements by their statistical correlation with test failures, using nothing more than pass/fail coverage. It is cheap to compute, but its ranking is diluted by every statement that happens to run alongside the fault, whether or not it is actually relevant.

This project evaluates a hybrid approach: instead of ranking every statement a failing test touches, it first computes the dynamic backward slice of each failing assertion, and restricts the suspiciousness ranking to that much smaller set of statements. The goal is not simply to report a raw hit rate across every fault, but specifically to measure the technique's success rate on the fault detections it could theoretically succeed at — and to characterize, systematically, why it fails on the rest: a structurally undetectable fault (dead code, or a line no test in the suite ever executes) is a fundamentally different failure mode from a genuine ranking miss on a line that was reachable all along.
